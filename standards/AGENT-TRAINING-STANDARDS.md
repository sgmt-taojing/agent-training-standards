# 智能体训练全流程规范 ASH v1.0（Agent Standards Hub）

> **ASH v1.0 · 智能体训练规范中心 · 2026-08-10 · 2026-08-11 品牌升级**
> 适用对象：任何组织/个人要训练自己的智能体，按本规范走完全流程。
> 定位：**领域无关**——本规范不倾向任何行业（医疗/金融/教育/命理/生活/工业均可适用），只定义「怎么把智能体训练好」的方方面面。
> 规范等级：**[必须]** 不满足不可上线 · **[应该]** 强烈建议 · **[建议]** 最佳实践
> 配套资产：规范各章对应的公共能力包见文末索引（中立选购，非强制）。

---

## 第 1 章 · 需求定义规范（先想清楚再动手）

**[必须] 训练目标声明（TGS, Training Goal Statement）**——开训前必须产出，模板：

```yaml
目标名称: <一句话描述智能体要做什么>
任务类型: 对话问答 | 行业专家 | 业务自动化 | 内容生成 | 数据分析
目标用户: <谁在用、什么场景、什么水平>
输入范围: <能接受什么输入；不能接受什么输入>
输出范围: <必须输出什么；禁止输出什么>
成功标准: <可量化的指标，如：领域问答准确率 ≥ 85%>
边界声明: <明确不做的事，越界时的兜底行为>
```

**[必须] 能力边界定义**：列出「能做什么 / 不能做什么 / 边界兜底话术」三列，训练数据与评测集都围绕边界设计。
**[应该] 场景清单**：列出前 30 个真实使用场景（含正向、边界、异常、对抗场景）。
**[应该] 角色定义**：智能体的角色人设、语气、表达风格（正式/亲切/权威）、语言（中英/多语）。
**[建议] 竞品基线**：选定 1-3 个参照对象，明确要超越的指标。
**验收**：边界声明可被评估集逐条验证 → 才算需求定义完成。

---

## 第 2 章 · 数据规范（训练的根基，占 70% 工作量）

**[必须] 数据来源白名单**：
- ✅ 自有业务数据（有合法使用权）
- ✅ 公开开源数据（MIT/Apache/BSD/CC-BY 等可商用协议，记录 license）
- ✅ 用户授权数据（有书面/电子授权记录）
- ❌ 付费墙内容、违反 ToS 爬取、无授权私人数据

**[必须] 数据清洗流水线**（每批数据过全流程）：
1. 去重（FTS5/SimHash 相似去重，重复率记录）
2. 去噪（乱码/截断/格式错乱/机器痕迹文本）
3. 脱敏（隐私四级：full_mask 全隐 / partial_mask 部分隐 / fuzzy 模糊 / blur 打码）
4. 格式规范化（统一 JSONL/对话格式）
5. 质量评分（可标注可机评，低质 <0.7 分不入库）

**[必须] 标注规范**：标注指南（含正反例）→ 标注 → 双人质检（抽检 ≥10%，一致率 ≥90%）→ 返工闭环。
**[必须] 数据分布设计**：边界场景 ≥20%、异常输入 ≥10%、对抗样本 ≥5%，防止「只会答正常问题」。
**[必须] 数据规模基线**：单领域问答 ≥ 5,000 条高质量样本起步；复杂任务 ≥ 20,000 条；每万条样本配 ≥ 500 条边界/拒答样本。
**[应该] 蒸馏规范**：外部知识蒸馏必须记录来源 + license + trust 分级（≥0.7 才入库），产出合规报告。
**[应该] 数据版本管理**：每批数据带版本号 + 变更说明，可追溯、可回滚。
**验收**：数据合规审计报告（来源/去重/脱敏/质检四项全绿）→ 才可进入训练。

---

## 第 3 章 · 训练规范（把数据变成能力）

**[必须] 基座模型选型**：记录选型理由（能力/成本/部署形态/协议），备选 ≥2 家防断供。
**[必须] 训练数据格式**：统一 ChatML 或等效多轮对话格式（system/user/assistant），工具调用任务用 function-calling 格式。
**[必须] 训练过程可复现**：固定随机种子、记录超参（学习率/批次/轮次/上下文长度）、保存 checkpoint。
**[应该] 分阶段训练**：
1. SFT（指令微调）：通用语料 → 领域语料，配比建议 1:3 起步，监控过拟合（训练/验证 loss 分叉即停）
2. 偏好对齐（DPO/RLHF）：偏好对 ≥ 数据集 5%，用同一分布，防偏好过拟合
3. 持续学习：小步增量（每轮 ≤ 原数据 10%），带旧知识巩固集，防灾难性遗忘
**[应该] 微调策略**：预算有限优先 LoRA/QLoRA（可插拔、可回滚）；全参微调需评估团队与算力。
**[必须] 禁用项**：禁止用测试集数据训练（数据泄漏）；禁止不记录版本就发版。
**验收**：训练卡（模型/数据/超参/资源/时间/成本）完整 → 才可进入评估。

---

## 第 4 章 · 评估规范（不测不算数）

**[必须] 评测集构建**（独立于训练集，专人隔离）：
- 领域正确性 ≥ 40%（标准答案可判定）
- 边界与拒答 ≥ 25%（不该答的必须拒答/兜底）
- 对抗与越狱 ≥ 15%（提示注入/角色越权/恶意输入）
- 一致性 ≥ 10%（同一问题多轮输出稳定）
- 风格与合规 ≥ 10%

**[必须] 核心指标**（发布门槛，全绿才可上线）：
| 指标 | 定义 | 门槛 |
|---|---|---|
| 准确率 | 领域问题答对比例 | ≥ 85% |
| 拒答率 | 边界问题正确拒答比例 | ≥ 95% |
| 幻觉率 | 无依据编造比例 | ≤ 3% |
| 越狱成功率 | 对抗样本突破比例 | = 0% |
| 延迟 P95 | 端到端响应 | 对话 ≤ 3s / 复杂任务 ≤ 10s |

**[必须] 回归测试**：每次版本迭代全量重跑评测集，指标下降即禁止发布。
**[应该] A/B 对比**：新版本与线上版本同题对比，人工盲评胜出才可灰度。
**[建议] 周评估**：每周自动化跑评测集 + 真实反馈抽样，输出趋势报告。
**验收**：评测报告（指标全绿 + 失败案例清单 + 修复计划）→ 才可上线。

---

## 第 5 章 · 上线规范（安全第一，灰度渐进）

**[必须] 部署防护**：鉴权（JWT/API Key）、限流（按客户分级）、熔断（超时/错误率阈值自动降级）、密钥托管（Keychain/加密存储，90 天轮换）。
**[必须] 灰度发布**：5% → 20% → 50% → 100%，每级观察指标（错误率/延迟/反馈）无劣化才放量。
**[必须] 监控告警**：错误率、P95 延迟、调用量、成本、用户反馈五项实时看板；异常自动告警。
**[必须] 回滚预案**：一键回滚上一版本（模型版本与数据版本双回滚）。
**[应该] 降级兜底**：模型不可用时返回友好提示 + KB 兜底答案，禁止白屏/静默失败。
**[应该] 日志审计**：关键交互留痕（输入/输出/版本/耗时），脱敏后存储，可追溯。
**验收**：上线检查单全绿（鉴权/灰度/监控/回滚/兜底）→ 正式发布。

---

## 第 6 章 · 运营进化规范（上线不是终点）

**[必须] 反馈闭环**：用户反馈（满意/不满意 + 评语）全量采集，聚合后进入下一轮训练。
**[必须] 使用日志回流**：调用量/场景分布/失败模式分析，识别能力短板。
**[应该] 版本管理**：semver（patch=修真 / minor=新能力 / major=破坏性变更），每版带 CHANGELOG。
**[应该] 持续蒸馏**：运营中发现的新知识按蒸馏规范入库（去重 + trust ≥0.7），周期性增量训练（建议 ≤ 每月一次，防遗忘）。
**[必须] 进化门槛**：无使用数据/无反馈的版本禁止空转发布（进化必须有输入）。
**验收**：每个季度产出《能力进化报告》（版本、指标趋势、新增能力、下一步）。

## 第 7 章 · 安全合规规范（红线，永久生效）

**[必须] 内容红线**（训练数据与输出双向扫描，命中归零）：
暴力/色情/赌博/毒品/诈骗/政治敏感/歧视仇恨（7 大禁止标签 + 行业扩展标签）。
**[必须] 隐私合规**：个人信息脱敏存储；生物特征（人脸等）匿名化；未成年人数据单独保护。
**[必须] 行业边界**：
- 医疗健康：不替代执业医师诊断；输出挂免责声明；诊疗类必须人工/医生审核（互联网医院模式）
- 金融投资：不承诺收益；输出带风险提示
- 法律/教育/命理等：挂载相应免责声明，不替代专业服务
**[必须] 提示词安全**：系统提示词不泄露；用户输入不可覆盖系统边界（注入防护）。
**[必须] 密钥管理**：所有密钥入 Keychain/加密托管，禁止明文落盘；90 天轮换；定期泄漏扫描。
**[应该] 审计合规**：数据合规报告、训练卡、评测报告、上线检查单四件套归档，随时可查。
**验收**：合规扫描脚本全绿（禁止标签 0 命中 / 密钥 0 明文 / 免责声明全覆盖）。

## 第 8 章 · 流程与协作规范（团队怎么跑）

**[必须] 角色分工**：需求方 / 数据工程师 / 训练工程师 / 评测工程师 / 上线运维，职责边界清晰（小团队可兼任但评测必须独立于训练）。
**[必须] 阶段门禁**：需求→数据→训练→评测→上线→运营，每阶段验收通过才放行下一阶段（PDCA 闭环）。
**[应该] 文档规范**：每个阶段产出对应文档（需求定义/数据报告/训练卡/评测报告/上线检查单/进化报告）。
**[应该] 迭代节奏**：每周迭代（小步快跑），月度里程碑（可演示交付）。
**[建议] 知识沉淀**：踩坑记录（修真日志）→ 沉淀为团队规范更新，防止同类问题复发。
**验收**：新成员按文档可独立走通一遍全流程。

## 第 10 章 · 公共能力资产索引（中立配套，按需选购）

本规范是**公共标准**，执行时可搭配通用能力资产（与具体领域无关的公共能力）：

| 资产 | 配套章节 | 形态 | 获取 |
|---|---|---|---|
| 训练体系能力包（数据生成/蒸馏/合规扫描/评估流水线） | 2/3/4/7 | L1 数据工具 + L2 技能 + L3 API | 能力包市场 |
| 智能体编排能力包（调度/记忆/KB 优先/自进化环） | 5/6 | L2 技能 + L3 API | 能力包市场 |
| 人机交互规范能力包（零学习成本/无障碍/个性化） | 1/5 | L2 技能 | 能力包市场 |
| 领域知识能力包（命理/中医/视觉等——按训练方向选购） | 2/4 | L1 数据 + L3 API | 能力包市场（领域可选） |
| 需求评估与匹配引擎 | 1 | 工具 | `scripts/capability-matcher.js` |
| 协议与边界模板（评估报告/授权协议） | 1/7 | 模板 | `templates/` |

> 中立声明：领域知识包仅为可选项，训练方可根据自身领域选配或不选；**规范本身与领域无关，全部章节通用**。


## 第 11 章 · 神经网络主流能力（12 维度选型）

智能体训练涉及的神经网络能力选型（**不是可选项**——2026 年起，以下能力已成为行业标配）：

- **知识检索**：N1 RAG 向量检索 / N2 GraphRAG 图谱检索 / N3 Agentic Search 智能搜索
- **微调优化**：N4 LoRA/QLoRA 参数高效微调 / N5 SFT 指令微调 / N6 DPO 偏好对齐 / N7 Continual Learning
- **多模态感知**：N8 Multimodal 融合 / N9 Voice 语音交互
- **智能体编排**：N10 Agent RL 强化学习 / N11 Function Calling 工具调用 / N12 Multi-Agent 协作

选型决策框架与门槛值详见 。

**[必须]** 训练方必须明确选用了 N1-N12 中的哪些能力（可全选或部分），并在训练卡中记录。
**[应该]** RAG 优先于微调（2026 行业共识）；微调首选 LoRA/QLoRA；偏好首选 DPO（非 RLHF）。
